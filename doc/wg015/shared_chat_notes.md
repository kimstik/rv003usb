# Конспект вводного чата (передан пользователем)

Источник: приватный чат-исследование пользователя (claude.ai share, вставлен текстом 2026-07-30).
Статус: рассуждения, не всё верифицировано по РП; сверять с chip_info.md.
**Директива пользователя, перекрывающая вывод чата: начинаем с исполнения из ФЛЕШ**
(«неравномерно, но детерминировано»), TCM — запасной вариант, не отправная точка.

## Состав стека
- rv003usb: 1092 строки asm + 497 строк C.
- Прецедент ретаргета уже в апстриме: ветка `CH32V00x` в rv003usb.S — ISR-секция в RAM
  (`.section .srodata,"ax"`), тайминг донастраивается макросами `VOOXDELAY` / `nx6p3delay`.
  Методика автора: добавление задержки на каждую ветвящуюся инструкцию закрывает почти
  все расхождения тайминга.
- Таргет-зависимое в asm: база GPIO + смещения CFGLR/INDR/BSHR; сброс EXTI->INTFR;
  SysTick 0xE000F000 (keep-alive); имя вектора EXTI7_0_IRQHandler; паддинги.
- Регистры — подмножество RV32E (zero..t2, s0, s1, a0-a5) → на RV32I BM-310 исполняется
  без изменений. NRZI, unstuffing, CRC, PID-диспетчер, TX-сериализатор — таргет-независимы.
  C-слой переносится как есть.

## Чип: К1921ВГ015 (по чату; верифицировать)
- Ядро: BM-310 (CloudBEAR), 2-стадийный, ~1 IPC, RV32I(+MC?).
- Память: TCM-A / TCM-B банки; флеш с prefetch-буферами 2×128 бит = 32 байта, CEN-бит.
- GPIO: DATA (вход), DATAOUTSET / DATAOUTCLR / DATAOUTTGL, направление OUTENSET/OUTENCLR,
  флаг прерывания INTSTATUS порта.
- Бонус-ручки, которых нет у V003: SYNCSET/SYNCCLR (входной синхронизатор пина),
  QUAL* (отключить квалификацию → мин. задержка), MASKLB — маскированная запись:
  модификация только D+/D- одним sw без RMW соседей (чтение через маску в РП не описано —
  не закладываться).
- Прерывания: mtvec direct → обработчик; если USB-пин — единственный разрешённый IRQ,
  mcause-диспетчер не нужен; PLIC claim/complete один раз в конце пакета перед mret
  (CSR-осушение конвейера — тоже только там).
- SysTick-замена: rdcycle (обёрнут в csr.h SDK) или TMR32.

## Тактовая арифметика
- 48 МГц целочисленной PLL → 32 такта/бит, паритет с V003. Дробный режим PLL НЕ брать:
  джиттер до периода FIN по РП.
- 50 МГц / 33 такта = 1.5151 Мбит/с (+1.01%, в допуске ±1.5%) — годится для TX, но на RX
  набегает 0.33 такта/бит; пофазной ресинхронизации внутри пакета в master нет
  (в handle_zero_bit — TODO, восстанавливается только полярность); на пакете ~90 бит
  ≈ битовый интервал. Итог: 48, не 50.

## Бюджет тайминга
- Допустимый сдвиг фазы выборки после преамбулы: −4..+6 тактов (комментарий в исходнике).
- Преамбульная петля ретаймится по фронтам (3 выборки GPIO на итерацию).
- Окно ~10 тактов на бит — бюджет, в который должны влезть отличия BM-310 (паддингами).

## Три числа, которых нет в РП (снять измерением)
1. Латентность lw из GPIO->DATA (пара rdcycle вокруг load; из TCM, мастера молчат).
   Критерий: побитовая работа ≈14-18 тактов при 1 IPC → load до ~6-8 тактов проходит
   паддингами; в преамбуле 3 load на ~64 такта → до ~10.
2. Вход в IRQ (фронт на пине → первая инструкция): тогл пина первой инструкцией + LA.
   Важен разброс, не абсолют (SYNC-паттерн ≈ 256 тактов съедается преамбулой).
3. Цена taken-branch BM-310: калиброванный цикл + rdcycle.

## Вывод чата (частично противоречит цели)
Чат рекомендовал код в TCM-A (стек и буфер в TCM-B), т.к. побитовая петля не помещается
в 32-байтовый prefetch и тайминг из флеша становится функцией состояния предвыборки.
Пользователь осознанно выбирает флеш-первым: при выключенном/фиксированном prefetch
тайминг медленнее, но детерминирован. Требуется измерительная фаза (см. PLAN.md).
