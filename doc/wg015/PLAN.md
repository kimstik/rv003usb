# План порта rv003usb (битбанг LS USB) + бутлоадера на К1921ВГ015

Статус: draft v1, 2026-07-31. База фактов: `chip_info.md` (+CORRECTIONS), `research/*.md`,
`stack_portability.md`, `branch_notes.md`, `shared_chat_notes.md`. Каждое решение ниже
опирается на верифицированный факт (ссылка в скобках) либо явно помечено «измерить».

## 0. Цель и рамки

Рабочий битбанг LS USB (1.5 Мбит/с) стек + USB HID бутлоадер на К1921ВГ015 @ 48 МГц,
32 такта/бит, код — во флеше (flash-first; TCM — измеримо обоснованный отход, не default).
База — master (branchless-ветка = cycle-exact артефакт CH32V003, branch_notes.md).
Не переделывать архитектуру при появлении третьего таргета.

## 1. Несущие факты (всё верифицировано, источники в chip_info.md/research/)

| # | Факт | Следствие для порта |
|---|------|---------------------|
| F1 | 48.000 МГц достижимы целочисленной PLL от HSE 10/12/16/20/24/25 МГц; fREF≥10 МГц; max SYSCLK 50 МГц | 32 такта/бит, паритет с V003; кварц 8 МГц не годится; HSI (1 МГц, ~5%) не годится |
| F2 | Флеш @48 МГц: LAT=1 (не 3!); префетч 2×128 бит, hit=0ws, miss=LAT; поверх — недокументированный I-cache 2К; фикс-тактность fetch НЕ гарантирована РП | flash-first возможен только через измерение; гейт G1 |
| F3 | RV32IMC — 1 такт/инструкцию (РП §8); CSR-доступ осушает конвейер; rdcycle есть | бюджет слота считаем от 1 IPC + измеренные дельты; CSR только вне побитового пути |
| F4 | GPIO: DATA(+0), DATAOUTSET/CLR/TGL, OUTENSET/CLR — атомарные W1; вход всегда за 2-тактным синхронизатором; Шмитта нет; INTSTATUS W1C; все порты → PLIC line 5 | RX: константная задержка входа (не джиттер); TX/turnaround проще, чем на CH32 (см. Р2-z3/z4) |

| F9 | HW USB официально сломан (эррата №3/№4), пины 30/31 не GPIO | битбанг — единственный путь; HW-блок вне рамок |
| F10 | IO: 3.3В, не 5V-tolerant, 4 мА, pull-up 18–360К (бесполезен) | внешний 1.5К DPU→D−; питание 3.3В; хост не должен питать D± при выключенном MCU |
| F11 | mtvec: SDK только direct; vectored не подтверждён | не закладываемся на vectored; вход через единый хендлер |
| F12 | Неизмерено нигде: цена lw из GPIO, вход в IRQ (такты+разброс), taken branch, fetch-стойлы, детерминизм I-cache | P1 — калибровка до любого портирования слотов |

## 2. Архитектурные решения

**Р1. База — master** (75d926a). Branchless-идеи (в первую очередь tier-b ACK-first,
3735518 — протокольная, самая переносимая) — только после P6 и только если измеренный
turnaround/eye этого потребует. Обоснование: branch_notes.md.

**Р2. Один исходник `rv003usb.S`, зонная параметризация — не форк-копия.**
py32 форкнул asm из-за смены ISA; здесь ISA совместима (RV32E-подмножество исполняется
на RV32I как есть, XW — 5 замен). Прецедент same-file параметризации — сам апстрим
(ветка CH32V00x: VOOXDELAY/nx6p3delay/секция RAM). Зоны изменений (полный список,
из stack_portability.md §3):
- z1: константы GPIO (база, смещения DATA/OUTEN*/DATAOUT*), маски пинов;
- z2: RX-сэмплы — `c.lw INDR` → `c.lw DATA(+0)` (только смещение/база);
- z3: TX-слот — запись BSHR → запись **DATAOUTTGL** (NRZI = toggle по нулевому биту:
  однa store, значение = 0 или D±-маска; семантически чище, чем set|clear-слово BSHR);
- z4: bus turnaround — вместо перезаписи CFGLR-ниблов: `OUTENSET=D±mask` (захват линий,
  1 store) / `OUTENCLR=D±mask` (отпуск, 1 store) + предустановка DATAOUT. Короче, чем у V003;
- z5: вход/выход ISR — mtvec(direct) → наш хендлер; ack: GPIO INTSTATUS W1C → PLIC
  claim(load MICC)/complete(store MICC) в хвосте пакета, строго INTSTATUS раньше complete
  (research_core_irq.md §4); mret. Хук пользовательских IRQ — по образцу
  RV003_ADD_EXTI_HANDLER: не-наш источник → бранч на слабый символ;
- z6: keepalive — SysTick CNT → rdcycle (CSR-осушение допустимо: путь вне битового цикла);
  HSI-trim-серво удаляется (кварц);
- z7: паддинги — свой WG015DELAY-набор по числам из P1 (механика VOOXDELAY).
Гарантия качества: **бит-идентичность** — сборка V003-таргета до/после параметризации
даёт идентичный бинарь (objcopy+cmp, добавить в Makefile как check-цель).
Отход: если зонная правка расползётся (>~30% строк под #if) — форк-копия
`rv003usb-wg015.S` соседним файлом (py32-паттерн); решение фиксируется в конце P3.

**Р3. C-слой единый.** Три шва py32 (заголовки/клоки; GPIO+IRQ init; макрос имени IRQ)
+ урок анти-паттерна: не `#if`-лестницы, а per-target включаемый `usb_port_wg015.h`
(инициализация, адреса, имена). `rv003usb.c` трогаем минимально.

**Р4. Тактирование.** HSE(кварц платы) → integer PLL → 48.000 МГц. Таблица конфигураций
для 10/12/16/20/24/25 МГц готова и проверена по диапазонам РП (research_clocks.md §2);
дефолт — 16 МГц (SDK-дефолт плат NIIET). LAT=1 (РП табл. 7.1), CEN — по результату P1.
Дробный режим PLL запрещён (нет спеки джиттера). REFSEL — противоречие РП/SDK,
разрешается экспериментом в P0 (research_clocks.md §1.2). Частотный запас: 48 < 50 max.

**Р5. Пины.** D+ = C0, D− = C1, DPU = C2 (маска D± = 0x03 → влезает в `c.andi`;
свободны на обеих платах NIIET; теряются только TMR32_OUT/UART-modem). Резерв: B2/B3/B4
(research_gpio.md §4). Внешний 1.5К DPU→D− обязателен. QUAL — off (default), SYNCSET —
base (2 такта, константа). D±-конфиг защитить LOCKSET.

**Р6. Размещение кода: placement-agnostic по построению.** Критический код (ISR RX/TX)
помечается секцией (механика `.srodata,"ax"` уже есть в апстриме для V00x). Линкер-скрипт
решает: FLASH (default, flash-first) или TCM-A (fallback; данные/стек — TCM-B, РП-рекомендация).
Это не оверинжиниринг — это один атрибут секции + две строки в ld; цена нулевая,
а переключение при провале G1 не трогает код. Гипотезы flash-first для P1:
- H1: горячий ISR (~1.2К) целиком садится в I-cache 2К → повторные пакеты детерминированы;
- H2: straight-line код в пределах префетч-буферов = 0ws (РП), miss только на дальних бранчах;
- H3: D-code приоритет → все данные ISR (буферы, таблицы) обязаны жить в RAM даже при коде во флеше.
H3 — принимается сразу как правило (дёшево); H1/H2 — измеряются.

**Р7. Прерывание.** mtvec (direct) указывает на наш хендлер. Первые инструкции — как в
V003 (сэмпл D− пятой инструкцией, затем 8-слотовый edge-catcher, поглощающий разброс входа).
Вход в хендлер обязан быть тактово-стабильным: если P1 покажет джиттер fetch на входе —
головной стаб (≈10 инструкций) кладётся в TCM-A всегда, остальное во флеше (гибрид,
не отменяющий flash-first). PLIC-приоритет: только наш источник > threshold; гарантия
невытеснения — свойством gateway (F5).

**Р8. Бутлоадер.**
- Лейаут: бутлоадер @ 0x8000_0000, бюджет **одна страница 4К** (ориентир: V003-лодер =
  1920 Б при жёсткой экономии; здесь без XW/ужимок — запас есть). App @ 0x8000_1000,
  фикс. точка входа; валидация перед прыжком (sp/entry в допустимых диапазонах).
- Вход в бутлоадер: (a) POR + таймаут ожидания USB-активности (механика V003-лодера),
  (b) опц. кнопка, (c) флаг в RTC_REG[0] + RCU.RSTSYS из приложения
  (замена BOOT_MODEKEYR/PFIC-механики, F8). RSTSTAT различает POR/SYSRST.
- Самопрошивка: механика V003 сохраняется — хост шлёт ≤120 Б блобы в RAM-скратчпад по
  HID feature reports, блоб исполняется. Блобы: unlock-free последовательность
  ADDR→DATA0..3→CMD(C0DE|WR / ERSEC)→5 NOP→poll BUSY; перед стартом — глобально IRQ off
  (F6: чтение флеша при BUSY = мусор, а SE0-keepalive дёргает ISR каждую мс);
  таймбейс-регистры TACCR..TPGSR пересчитать на 48 МГц один раз при старте лодера.
  Юнит записи 16 vs 64 Б — тест на железе первым блобом.
- Хост-утилита: паттерн `busbflash.c` (hidapi, уже в репо) — расширить до полноценной
  CLI (erase/write/verify/run) с блобами WG015. minichlink не трогаем.
- Первичная заливка/анбрик: OpenOCD (форк DCVostok), SERVEN — крайний случай.
  CFGWORD (JTAGEN/FLASHWE) не трогаем вообще.
- `USE_TINY_BOOT`-аналог: свой минимальный старт (sp, mtvec, zero-RAM, PLL 48, LAT=1) —
  замена WCH-блока S:1032-1085.
- Linker: SECRET-механика (XOR-адрес boot_usercode по фикс. смещению) переносится как есть,
  адреса — новые; скратчпад — фикс. адрес в TCM-B.

**Р9. Сборка.** `Makefile.wg015` поверх тех же демо-каталогов (py32-паттерн:
`make -C demo_hidapi -f ../Makefile.wg015`). Тулчейн riscv-none-elf GCC 13.2
(14.x — битые мультилибы, research_errata.md §4), `-march=rv32imc_zicsr -mabi=ilp32`
(FPU не используем — обходим эррату №5 стороной). Из SDK берём только `K1921VG015.h`
(+системные мелочи) — вендорим в `rv003usb/wg015/` с указанием источника/лицензии;
submodule на gitflic не заводим, пока не потребуется больше двух файлов (KISS; решение
пересмотреть, если файлов станет >3). Старт/ld — свои (они и есть предмет порта).

## 3. Тайминг-модель

Бюджет: 32 такта/бит; допуск сдвига фазы выборки −4..+6 тактов после преамбулы (S:186-188);
преамбула ретаймится по фронтам; вход ISR съедается SYNC-паттерном (8 бит ≈ 256 тактов) —
важен разброс, не абсолют. Отличия от V003, ложащиеся в это окно:
- lw из GPIO->DATA: **измерить** (в бюджете проходит ≤6-8 тактов, shared_chat_notes.md);
- taken branch BM-310: **измерить** (РП молчит; 2-стадийный конвейер → ожидание 1-2);
- fetch из флеша: **измерить** H1/H2 (F2, F12);
- вход в IRQ: **измерить** разброс (константная часть неважна);
- +2 такта входного синхронизатора — константа, сдвигает фазу, не джиттер (F4);
- нет Шмитта (F4): медленные фронты LS (до ~300 нс = 14 тактов) могут дребезжать на
  одиночных сэмплах — риск R5, мониторить на soak-тесте, лечится последовательным R/RC.
Замеры — rdcycle-парами и пин-тоглом + LA; методика в P1. Симулятора для BM-310 нет —
не строим (анти-скоуп), меряем на железе.

## 4. Фазы

Каждая фаза: коммит(ы) + push + обновление STATE.md. Артефакты фаз — в doc/wg015/.

**P0. Стенд** (блокер — железо у пользователя, §7 в.1-2)
Тулчейн 13.2 + OpenOCD DCVostok + плата; blink через OpenOCD; UART-консоль (A0/A1);
PLL 48 МГц: REFSEL-эксперимент (оба значения, CKO на C7 = 48/2^n на частотомер/LA);
rdcycle работает. Выход: репо-каталог `wg015_bench/`, зафиксированный клок-конфиг.

**P1. Калибровка** (решающая фаза)
Микробенчи (всё в `wg015_bench/`, результаты → `doc/wg015/calibration.md`):
1. lw/sw GPIO из TCM: rdcycle-пары, мастера молчат;
2. taken/untaken branch, выровненный/невыровненный таргет;
3. вход в IRQ: фронт на пине → тогл первой инструкцией; LA: медиана + разброс; хендлер
   в TCM vs во флеше — отдельно;
4. fetch-профиль флеша: (а) straight-line 1К инструкций, rdcycle: тактов/инстр при LAT=1
   холодный/горячий прогон (H1: повтор == повтор?); (б) петля с бранчем через 32 Б
   (гарантированный miss) — цена miss; (в) CEN=0 vs CEN=1 — семантика на живом железе;
   (г) то же из TCM — референс;
5. эмуляция слота: синтетический 32-тактный цикл (load-DATA + работа + store-TGL) из
   флеша и из TCM, LA на выходном пине: гистограмма периодов — прямой ответ «дрожит или нет».
**Гейт G1** — выбор размещения: per-slot джиттер ≤±2 тактов и суммарный дрейф на 90-битном
пакете в окне −4..+6 → флеш (CEN по результату 4в); иначе — ISR-секция в TCM-A
(placement-переключение из Р6, кода не трогает). Головной стаб ISR — по бенчу 3.
Выход: calibration.md с числами + решение G1 записано.

**P2. Скелет таргета**
`rv003usb/wg015/`: вендоренный заголовок, startup (свой, минимальный), `wg015_flash.ld`
(+критическая секция по Р6), `usb_port_wg015.h`, `Makefile.wg015`; demo-каркас собирается,
IRQ от кнопки через наш mtvec-хендлер работает, 1 мс-тик по rdcycle совпадает с LA.
Выход: зелёный «скелет» + бит-идентичность V003-сборки (check-цель Р2).

**P3. RX**
Зоны z1/z2/z5/z6/z7 в rv003usb.S; паддинги по P1; приём реального трафика хоста:
SETUP/токены ловятся, буфер корректен (дамп в UART), CRC сходится. Критерий: ≥10 мин
непрерывного приёма токенов без потерь (счётчики). Тут же — решение Р2-отхода
(зоны разрослись? — нет/да, фиксируем).

**P4. TX + энумерация**
Зоны z3/z4; ACK; usb_send_data; турнэраунд-тайминг по LA (спека: ответ ≤7.5 бит-тайма);
полная энумерация на Linux/Windows-хосте, demo_hidapi ходит feature-репортами.
Критерий: стабильная энумерация ≥100 подряд переподключений, soak ≥1 ч без wedge,
счётчики ошибок ~0, dmesg чист.

**P5. Бутлоадер**
По Р8: лейаут, вход, блобы (первый блоб — тест юнита записи 16/64 Б), пересчёт
TACCR..TPGSR, хост-CLI из busbflash; testblink-цикл. Критерий: 100 подряд циклов
reflash→run→soft-reset→reflash без JTAG-вмешательства; JTAG-анбрик отработан документированно.

**P6. Стабилизация**
Eye-запас: варьирование частоты хоста недоступно — вместо этого маргин-тест паддингами
(±1 такт искусственного сдвига сэмпла → карта запаса); README-wg015; ревизия анти-скоупа
(нужен ли tier-b ACK-first — по измеренному турнэраунду); финальная чистка diff.

| R10 | Лимиты/обрывы сессий | постоянно | всё в файлах repo, коммит на каждом шаге, STATE.md ведётся |

## 6. Анти-скоуп (сознательно не делаем)

Порт branchless RX/TX v2 (артефакт 32-тактных леджеров V003); HW-USB блок; дробная PLL;
50 МГц/33 такта (набег 0.33 такта/бит без пофазного ресинка — отвергнуто, shared_chat_notes.md);
симулятор BM-310; RAM-first (только как измеримо обоснованный отход R1/R2); поддержка
кварцев <10 МГц; изменения C-протокольного слоя сверх швов Р3.
