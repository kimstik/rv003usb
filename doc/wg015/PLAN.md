# План порта rv003usb (битбанг LS USB) + бутлоадера на К1921ВГ015

Статус: **v3 (final draft)**, 2026-08-01. Самодостаточен (ссылок на v1/v2 нет).
Прошёл два раунда адверсариального ревью (5 линз, redteam_findings.md); интегрированы
все blocker/major и принятые minor. База фактов: `chip_info.md` (+CORRECTIONS),
`research/*.md`, `stack_portability.md`, `branch_notes.md`, `shared_chat_notes.md`.

## 0. Цель и рамки

Рабочий битбанг LS USB (1.5 Мбит/с) стек + USB HID бутлоадер на К1921ВГ015 @ 48 МГц,
32 такта/бит. Код — во флеше (flash-first); TCM — только как измеримо обоснованный отход.
База — master (75d926a); branchless-ветка — cycle-exact артефакт CH32V003, не база.
Архитектура рассчитана на третий таргет без переделки (§Р2: макро-контракты).

**Честная формулировка flash-first.** Документированный префетчер (2×128 бит, hit=0ws,
miss=LAT) покрывает только straight-line код; реальный RX ветвится по данным между
путями, разнесёнными на ~300 Б (S:298-424) — на уровне документированного железа промах
почти на каждом бите. Флеш-исполнение жизнеспособно, если **кэш команд 2 КБ** делает
многопутевую петлю повторяемо-детерминированной. Вердикт research_bm310.md: кэш — опция
ядра BM-310S6 (CloudBEAR; у sibling-Миландра BM-310S кэша нет), кэш-CSR нет, только
fence.i → **неотключаем**; CEN, вероятно, гейтит НИИЭТ-овский префетч (проверка — P1.4в).
Следствия: G1-бенч с вытеснителем — единственный честный тест; fence.i — легальный
способ форсировать холодный старт в бенчах. Разбор `-mfix-cloudbear-0001` (эррата №5):
NOP нужен перед fdiv/fsqrt И div/rem при операнде, загруженном из флеша → загрузки
данных из флеша имеют переменную латентность — микроархитектурное доказательство
правила «данные тактованного пути только в TCM/регистрах» (Р3). TCM подтверждён:
два независимых порта 128К/32-бит, 0-wait, конфликт только I+D на одном порту.

## 2. Архитектурные решения

**Р1. База — master.** Branchless-идеи — после P6 по измерениям (tier-b ACK-first — R9).

**Р2. Один исходник `rv003usb.S`; чип-специфика — именованные по-сайтовые
макро-контракты, не #if-колонки.** (Урок анти-паттерна py32 + требование «третий чип
без переделки».) Тело .S ссылается только на макросы; каждый таргет определяет их один
раз в `usb_port_<chip>.h`. Прецедент механики — VOOXDELAY/nx6p3delay самого апстрима.

**Реализационное упрощение (найдено при имплементации, машинно проверено):** окно
**MASKLB** (`base+0x400+(USB_DMASK<<2)`) — точный семантический эквивалент BSHR:
аппаратно-маскированная АБСОЛЮТНАЯ запись только битов D± (DPU на том же порту не
затрагивается). `BSHR_OFFSET` для WG015 просто переопределяется на MASKLB-окно, s1
остаётся абсолютным состоянием пары, t1 — флип-словом (=USB_DMASK), и TX-движок
сохраняет идентичный поток инструкций; меняются только li-константы трёх абсолютных
сайтов (preset K, SE0, J-park). Таблица ниже — контрактная семантика; MASKLB-реализация
её удовлетворяет. Бит-идентичность V003 и V00x подтверждена ассемблированием и
сравнением бинарей (scratchpad bitcheck, gcc 13.2).

Контракты (по всем hw-сайтам из stack_portability.md §3):
| Макрос | Семантика | V003 | WG015 |
|---|---|---|---|
| USB_SAMPLE(rd) | чтение D± одним load | c.lw INDR(+8) | c.lw DATA(+0) |
| USB_TX_PRESET | абсолют K до захвата | BSHR-слово | DATAOUTSET=DP; DATAOUTCLR=DM (2 store, до OUTEN!) |
| USB_TX_ACQUIRE / RELEASE | захват/отпуск линий | CFGLR-ниблы (2МГц-режим!) | OUTENSET=D± / OUTENCLR=D± |
| USB_TX_TOGGLE | NRZI-тогл (преамбула S:837, zero-бит S:948, стафф S:1024) | BSHR set/clr-слово | DATAOUTTGL=D±mask |
| (one-bit путь S:914-927) | **store отсутствует** | — | — (паритет тактов балансирует z7) |
| USB_TX_SE0 | обе линии вниз (S:992) | BSHR clr-слово | DATAOUTCLR=D±mask |
| USB_TX_PARK_J | J-park (S:997) | BSHR-слово | DATAOUTSET=DM (DP уже 0 после SE0) |
| USB_ISR_ACK | сброс запроса | EXTI_INTFR W1C | GPIO INTSTATUS W1C → PLIC complete (порядок строго такой) |
| USB_TICK_READ(rd) | HCLK-счётчик | SysTick CNT | rdcycle |
| USB_TRIM_ACTUATE | актуатор серво | RCC.HSITRIM | пусто (кварц) / резерв CLK-B |
| XW_C_LBU/LHU/SB (5 сайтов, S:439/477/485/665/**890 — в тактованной TX-петле**) | байтовые операции | XW-инструкции WCH | стандартные lbu/lhu/sb (32-бит! — леджер z7 и P1.5-эмуляция учитывают смену длины) |
| WG015DELAY / TUNE-пад | паддинг | VOOXDELAY/nx6p3delay | нопы / jr-в-nop-след (Р10) |

Инварианты: DATAOUT-биты D± валидны перед каждым захватом (J-park держится между
пакетами); PRESET строго до ACQUIRE. Паддинг-зоны и маркеры Р10 — часть леджера каждого
слота; z7 перебалансирует изменившиеся последовательности (не только адреса store).
Трамплины z8 (far-branch asm↔C для TCM-варианта, механика V00x `lui/addi+c.jr`,
S:465-470/497-515) готовятся в P2 — отход R1 становится действительно link-time
(флеш и TCM разнесены на 1 ГБ, `c.beqz`→C-хендлер не дотягивается; «цена нулевая» — неправда).

Гейт форк-копии: метрика = **новые WG015-условные строки / всего** (в файле уже 300/1092
строк под #if для V003/V00x — старые не считаем); решение — **в конце P4** (когда
существуют тяжёлые зоны TX/turnaround), порог ~15% новых строк или несводимость
семантики к макросам. Гарантия: **бит-идентичность V003 И V00x сборок** до/после
(check-цель Makefile: objcopy+cmp, V00x — сборкой bootloader_v006).

**Р3. C-слой единый. Четыре шва** (три py32 + один новый):
1) заголовки+клоки; 2) GPIO/IRQ init; 3) макрос имени IRQ; 4) **REBOOT_TO_BOOTLOADER()**
— rv003usb.c:179-184 (WCH BOOT_MODEKEYR/PFIC-сброс) оборачивается макросом из
usb_port_<chip>.h; WG015: `RTC_REG[0]=флаг; RCU->RSTSYS=A55A|RSTEN`. Это явное
исключение из анти-скоупа, назначено P5.
Правило данных: **всё, что читается в тактованном пути — в RAM** (дескрипторы читаются
побайтно изнутри TX-слота, S:887-890, а D-code имеет приоритет над I-code + переменная
латентность флеш-загрузок по эррате №5). Реализация — линкером: .rodata конфигового TU
в data-секцию (копирует стартап), кода не трогает.

**Р4. Тактирование.** HSE→integer PLL→48.000 (конфиги для 10/12/16/20/24/25 МГц
верифицированы по диапазонам РП, research_clocks.md §2; дефолт 16). Дробный режим
запрещён. REFSEL — противоречие РП/SDK, эксперимент P0. LAT=1 — рабочая гипотеза с
integrity-гейтом (R11): вендор ездит на LAT=3, эррата №5 доказывает флеш-hazard'ы,
РП-таблицы ошибаются (прецедент ADCSD); эскалация LAT=2 = полный перезапуск P1.

**Трек CLK-B (параллельный): без кварца — целевой уровень.** Кварц — стартовая ступень.
Документированного пути нет (fREF 10-30 МГц, fVCO≥200 при FBDIV≤160, HSI ~1 МГц —
вдвое не дотягивается). Исследовательские ходы (не блокируют основной трек):
out-of-spec PLL от HSI через REFSEL=0 (мультиплексор физически есть, рис. 4.1);
поведение VCO ниже минимума; HSI_TRIM (шаг ~8%/LSB — груб); запрос NIIET/CloudBEAR.
Страховка в архитектуре: серво-хук z6 расслоен — замер SE0→SE0 кадра общий,
USB_TRIM_ACTUATE — плагин; найдётся путь — бескварцевый уровень включится конфигом.

**Р5. Пины.** D+=C0, D−=C1, DPU=C2; резерв B2/B3/B4. Внешний 1.5К DPU→D−. QUAL off,
SYNC base (2 такта — константа фазы). LOCKSET на D± **запрещён** (F4: залоченный пин
не принимает DATAOUT*/OUTEN* — TX умер бы; ред-тим arch-1). С P0 на плате: посадочные
места последовательных R на D± и, эскалацией, внешнего буфера 74LVC1G-класса (R12).

**Р6. Размещение кода: placement-agnostic.** Критические секции маркируются; линкер
решает FLASH (default) | TCM-A (+данные/стек в TCM-B — банк-сплит обоснован
двухпортовостью TCM). Отход = смена размещения + активация z8-трамплинов.
Гипотеза H1: горячее множество (**asm-ISR + C-хендлеры turnaround-пути**, c:162-238)
детерминированно сидит в I-cache — проверяется P1.5 с вытеснителем.

**Р7. Прерывание.** mtvec(direct) → наш хендлер; сэмпл D− 5-й инструкцией; 8-слотовый
edge-catcher. Приоритеты: наш источник prio 7; прочие — ниже нашего, **выше threshold**;
невытеснение — mstatus.MIE=0 на весь трап; gateway страхует только same-source.
Контракт чужих хендлеров ≤~40 тактов. Диспетчеризация «не-наших»:
- чужой PLIC-источник → по значению claim из MICC → слабый символ;
- **чужой GPIO-пин (тот же claim=5!)** → по битам INTSTATUS: ранняя проверка
  `INTSTATUS & ~USB_DMASK` → слабый хук + W1C (порт паттерна RV003_ADD_EXTI_MASK,
  S:78-83/554-563; ред-тим complete-4).
Жёсткий гейт входа (P1.3): keepalive-SE0 = 2 бита = 64 такта, классификация первым
сэмплом → медиана(фронт→1-я инстр) + 4 инстр + lw GPIO + 2 такта синхронизатора
**≤ ~55 тактов**; провал = головной стаб в TCM-A обязателен (и переход стаб→тело меряется).

**Р8. Бутлоадер.**
- Лейаут: лодер @0x8000_0000, бюджет 4К = 1 страница (оценка ред-тима: V003-функционал
  ~1.9К на RV32EC + ~1-1.5К оверхеда PLL/PLIC/startup/far-адресация — влезает; R8 = 8К);
  app @0x8000_1000 (параметризовано).
- **Вход**: POR+таймаут (таймаут — **rdcycle-дельта**, не счётчик итераций: V003-константа
  «75 мс/юнит» калибрована под скорость петли V003, boot.c:270-298); опц. кнопка;
  reboot-запрос из app. Флаг RTC_REG[0] — **one-shot** (читается и немедленно чистится)
  и учитывается **только при RSTSTAT=SYSRST** (не POR) — иначе застрявший флаг при
  VBAT-питании переживает полный цикл питания (boot-6).
- **Выход в app — контракт передачи** (boot-1-blocker; у V003 это был аппаратный
  boot-свитч+сброс, здесь его нет): fast-path в старте лодера — если флаг «boot app»:
  очистить флаг → прыжок в app **до** включения USB/PLIC/DPU (около-сбросовое
  состояние). Обычный путь (таймаут/нет хоста): выключить USB-состояние по контракту —
  MIE=0; INTSTATUS очищен; MICC completed; MIEM0 источник выключен; mtvec — на app
  или сброшен; **DPU отпущен** (дисконнект-пульс ≥1 с логики V003 boot.c:105-108 —
  app сам решает, поднимать ли USB); клоки: app получает настроенные 48 МГц + LAT
  (документировано в README порта). Валидация перед прыжком: sp/entry в допустимых
  диапазонах.
- **Самопрошивка**: хост шлёт блобы в RAM-скратчпад (1152 Б, SCRATCHPAD_SIZE boot.c:68;
  лимит 120 Б — только кадрирование одного репорта, стриминг-продолжение есть
  device-side, boot.c:453-471) по HID feature reports; блоб исполняется с mstatus.MIE=0
  до BUSY=0 (F6). **Каждый erase/write-блоб начинается с адрес-гварда**: reject
  ADDR < app_base, запрет ALLSEC/NVRON (~4 инструкции); хост-CLI независимо отказывает
  адресам ниже app_base (R14: лодер — обычная страница 0, сам себя стирать не должен;
  восстановление только SERVEN+JTAG). Таймбейс-регистры TACCR..TPGSR пересчитываются
  на 48 МГц один раз при старте лодера. Первые блобы P5 **меряют** реальные времена
  page-erase и program (rdcycle в блобе → readback через скратчпад) и юнит записи 16/64 Б.
- **Пейсинг хоста** (boot-3: erase 4К-страницы — многомиллисекундное мёртвое окно USB,
  таймбейс TERSR = 100 мс-масштаба): протокол CLI — никаких transfer'ов в полёте во
  время блоба; послать блоб → ждать измеренное время + маржа → поллить с ретраями,
  толерантными к проваленным control transfer'ам; стирание попстраничное между
  обменами. Референс busbflash (слепой usleep(20000), без ретраев) — только скелет.
- **P5 стартует со спецификации wire-протокола** device-side (кадрирование, продолжение,
  магический трейлер 0x1234abcd, readback, SECRET) + перечня блобов: rescale-timings,
  erase-page, program-chunk, boot-app (boot-4; minichlink-референс недоступен —
  сабмодуль пуст).
- **SECRET**: хранится **смещение** boot_usercode от 0x8000_0000 (влезает в 16 бит при
  4-8К лодере) с тем же XOR-фолдом как integrity; V003-формула паковала полный адрес
  в 16 бит — на 0x8000_xxxx она молча ломается (boot-5).
- **Идентичность устройства**: VID/PID 1209:B003 сохраняем, **bcdDevice бампаем** —
  CLI обязан верифицировать чип до посылки блобов (блоб не того чипа = кирпич-вектор);
  udev-правило — в README CLI (complete-8).
- Первичная заливка/анбрик: OpenOCD DCVostok; SERVEN — крайний случай. CFGWORD не трогаем.
- Свой tiny-boot: sp, mtvec, zero-RAM, PLL 48, LAT — замена WCH-блока S:1032-1085.

**Трек BOOT-B (параллельный, отдельный бранч): DFU-лодер.** База —
kimstik/SAMDx1-USB-DFU-Bootloader (форк majbthrd, ~1К, control-only). Мотивация:
(а) DFU нативно решает мёртвое окно флеша — bwPollTimeout в GETSTATUS вместо
самодельного пейсинга CLI (закрывает boot-3/R-пейсинг); (б) хост = стандартный
dfu-util, wg015hostcli не нужен; (в) control-only = ровно возможности стека.
Отличия от blob-схемы: процедуры записи внутри лодера (write-рутина копируется в TCM
на время BUSY — no-read-while-write), меньше гибкость, больше самодостаточность.
Адрес-гвард обязателен так же. Топология: бранч поверх ядра порта после P4
(стек общий, различается только прикладной слой); дефолтный лодер выбирается по
размеру/живучести на железе. До P4 — не начинать (нечем дышать без энумерации).

**Р9. Сборка и швы (spec — чтобы не импровизировать в P2; ред-тим arch-5).**
- Шим-заголовок: каталог `rv003usb/wg015/` содержит **свой `ch32fun.h`** (шим),
  выбирается `-I` — включения S:1/c:10 не трогаются. Шим предоставляет: регистровые
  структуры (из вендоренного K1921VG015.h), XW_C_* → стандартные, SysTick-замену,
  NVIC_EnableIRQ-аналог (PLIC), DEBUG-sink адрес, `FUNCONF_SYSTICK_USE_HCLK 1`
  (rdcycle HCLK-синхронен — гвард h:17-19 удовлетворяется, не зонится).
- `Makefile.wg015` поверх тех же демо-каталогов (py32-паттерн); цели: elf/bin/lst,
  flash (OpenOCD), check-битидентичность V003+V00x, секция бутлоадера.
- Per-demo конфиги: funconfig/usb_config кондиционируются по таргету (py32-прецедент);
  **demo_hidapi не chip-clean** (WS2812-DMA-драйвер WCH + пины порта D) — LED-блок под
  `#if !WG015`, пины per-target (complete-3).
- Тулчейн GCC 13.2 riscv-none-elf, `-march=rv32imc_zicsr` (без F — эррата №5 стороной).
- **Лицензия SDK — проверить в P0** и записать вердикт: вендорить K1921VG015.h можно
  только если редистрибуция разрешена; иначе — submodule gitflic или генерация
  минимального заголовка из SVD (arch-8).
- Флаги usb_config на WG015: поддержаны OPTIMIZE_FLASH, HANDLE_IN_REQUEST,
  OTHER_CONTROL, HANDLE_USER_DATA, HID_FEATURES, BOOTLOADER, USE_REBOOT_FEATURE_REPORT;
  **RV003USB_USB_TERMINAL = #error** (тянет WCH swio_self.h) (complete-5).

**Р10. Наблюдаемость: маркеры нулевой интрузивности + hw-in-loop тюнинг.**
- Маркер = всегда присутствующий `sw dbg_mask, DATAOUTTGL(port)`; TGL с нулём —
  архитектурный no-op: debug on/off отличаются только данными, поток инструкций и
  такты идентичны. Маски — в TCM-переменных, грузятся при входе в ISR (рантайм,
  без перепрошивки). Store — член 32-тактного леджера (цена из P1.1).
- **DBG0 «сетка»** (тогл у каждого RX-сэмпла; границы TX-ячеек): **дефолт — B2**
  (свободный пин, чистое измерение). **DPU-режим DBG0 — опция конфига**: пин подтяжки
  можно тоглить в окнах, где шина активно ведётся (драйвер ~100 Ом против 1.5К —
  инъекция ~200 мВ в ведомую линию: далеко от порогов, но заметно в глазе — для
  прецизионных eye-замеров канал B2). Правило DPU-режима: тоглы только при ведомой
  шине + безусловный re-park `DATAOUTSET=DPU` в некритичном хвосте перед отпусканием.
- **DBG1 «события»** (1-я инструкция ISR, done_preamble, SE0/keepalive, старт/конец TX):
  C3, опционален (не распаян — маска 0).
- TUNE-паддинг: в TUNE-сборке паддинг-макрос = `jr` в nop-след со смещением из
  TCM-переменной (гранулярность 1 такт, под LA в рантайме); финальные константы
  запекаются в продакшн-нопы, маркеры верифицируют. P1-бенчи используют эти же макросы.
- Бонус RV32I: x16+ свободны от E-чистого asm — внутри ISR под маски/базы (постоянная
  резервация запрещена — C-ABI).

## 3. Тайминг-модель

32 такта/бит. Окно −4..+6 (S:186-188) — стартовый фазовый допуск V003-сборки, **не
переносимая константа**: на ВГ015 перевыводится TUNE-свипом (P3). Бюджет дрейфа: пакет
до **~102 слотов** (88 бит + worst-case стаффинг). Ошибки слотов интегрируются в фазу
(ин-пакетного ресинка в master нет) → критерии G1 — по кумулятивной экскурсии.
Статический паддинг лечит только детерминированные константы путей; истинная
случайность = провал флеша. Вход ISR: константная часть ограничена keepalive-окном
(≤~55 тактов, Р7), разброс — edge-catcher'ом. Выход: tail+re-entry < ~200 тактов
(хост-ACK через ~2 бита + SYNC ≈ 300 тактов после нашего EOP).

## 4. Фазы

**Порядок исполнения: код — сейчас, железо — посттюнинг.** Весь порт (P2-P5) пишется
немедленно по статической аналитике: модель 1 такт/инструкция (РП §8) + известные
константы; все неизвестные величины (branch penalty, латентности GPIO/MICC, вход в IRQ,
флеш-поведение) — параметры паддингов в `usb_port_wg015.h` + TUNE-ручки Р10, не блокеры.
P0/P1 выполняются по появлении железа как **валидационно-тюнинговый проход**: бенчи
(уже готовые прошивки) снимают числа → константы паддингов обновляются в одном месте →
G1 решает размещение → TUNE-свип затягивает фазу. Ниже P0-P6 описывают содержание работ;
статически исполнимо всё, кроме отмеченного меткой [HW].

Каждая фаза: коммит(ы)+push+STATE.md. Артефакты — в doc/wg015/.

**P0. Стенд.** Тулчейн 13.2 + OpenOCD DCVostok + плата; blink; UART-консоль (A0/A1);
PLL 48 МГц (REFSEL-эксперимент; CKO на C7); rdcycle работает.
Выход-чеклист: маркировка чипа записана (R13); **холодный старт blink с 0x8000_0000**
(верифицирует reset-PC, F7); LA ≥100 МС/с подтверждён (замена — input-capture TMR32,
хуже); посадочные места R и буфера на D± (Р5); **вердикт по лицензии SDK** (Р9);
`wg015_bench/` каркас в репо.

**P1. Калибровка** (`wg015_bench/` → `calibration.md`; все числа помечаются LAT).
Правила: rdcycle — только агрегатно; пер-слотовые времена — только LA (маркеры Р10).
1. lw/sw GPIO из TCM (агрегатные rdcycle-пары);
2. taken/untaken branch (penalty 0 или 1?); выровненный/невыровненный таргет;
3. вход в IRQ: фронт→тогл 1-й инструкцией; медиана И разброс; хендлер в TCM и во
   флеше; **гейт ≤~55 тактов** (Р7); переход TCM-стаб→flash-тело;
4. флеш-профиль: straight-line; бранч-мисс за 32 Б; CEN=0/1 (семантика на железе —
   заодно ответ «CEN = префетч?»); TCM-референс; **integrity-стресс LAT=1** (чек-суммы
   большого региона, длительно) — прекондиция G1 (R11);
5. слот-эмуляция, **изоморфная реальному коду**: ≥3 тела слота на расстояниях 100-300 Б,
   выбор по PRBS, обратный бранч каждый слот (или ранний порт RX-скелета z1/z2 как
   генератор); из флеша и TCM; **вытеснитель** (между «пакетами» >2-4К постороннего
   флеш-кода; один под-путь холодный серединой пакета; fence.i для форсирования);
   лог кумулятивных сумм, ≥10^4 пакетов, cold vs warm; в TX-эмуляции — lbu-сайт S:890;
6. lw/sw MICC и INTSTATUS; back-to-back IRQ: полный хвост + перевход, зазор по LA.
**Гейт G1**: флеш проходит, если при integrity-чистом LAT и активном вытеснителе:
(а) каждый путь повторяемо-детерминирован (нулевая дисперсия) — пути триммируются
z7-паддингом в ровно 32; либо (б) worst-case кумулятивная экскурсия по скользящим
окнам ≤102 слотов на ≥10^4 PRBS-пакетов ⊂ перевыведенный допуск (P3-свип) − 2 такта
запаса − константа синхронизатора. Иначе — TCM-A + z8. Головной стаб — по бенчу 3.

**P2. Скелет таргета.** `rv003usb/wg015/`: шим-`ch32fun.h` (инвентарь символов из Р9),
вендоренный/сгенерированный K1921VG015.h, tiny-startup, `wg015_flash.ld` (+критическая
секция Р6 + data-размещение дескрипторов Р3), `usb_port_wg015.h` (макро-контракты Р2),
`Makefile.wg015`, z8-зона заготовлена. Демо-каркас собирается, IRQ от кнопки через наш
mtvec-хендлер, 1 мс-тик rdcycle совпадает с LA. Выход: скелет зелёный +
бит-идентичность V003 и V00x сборок.

**P3. RX.** Контракты USB_SAMPLE/ISR_ACK/TICK_READ + паддинги z7 по P1; TUNE-свип →
карта допуска на цели (кормит G1-(б)); положение сэмпла в глазе — по DBG0; приём
реального трафика: SETUP ловится, CRC сходится, ≥10 мин без потерь (счётчики).

**P4. TX + энумерация.** Контракты USB_TX_* (по-сайтовая таблица Р2) + lbu-замена
S:890; ACK; турнэраунд ≤7.5 бт по LA; TX-фронты D± на разъёме против конверта
75-300 нс (R12, обе ветки); энумерация, demo_hidapi (LED-блок за #if, пины per-target);
≥100 переподключений, soak ≥1 ч, dmesg чист. **Фиксация решения форк-гейта Р2**
(метрика новых условных строк — теперь весь diff существует).

**P5. Бутлоадер.** Спецификация wire-протокола + перечень блобов (первый шаг, Р8);
лейаут; вход/выход по контракту Р8; блобы с адрес-гвардом; измерение erase/program
времён и юнита записи; пейсинг CLI; REBOOT_TO_BOOTLOADER() шов в C (Р3.4); SECRET-офсет;
bcdDevice-бамп + верификация чипа в CLI; testblink-цикл. Критерий: 100 подряд циклов
reflash→run→reboot→reflash без JTAG; SERVEN-анбрик отработан документированно.

**P6. Стабилизация.** Регресс маргин-карты на финальном коде; README-wg015 (вкл.
контракт клоков app, udev, идентичность); ревизия анти-скоупа (tier-b — по измеренному
турнэраунду); чистка diff; финальная бит-идентичность V003/V00x; **трим-проход лодера** (цель ≤2К: ужать startup ~50-80 Б, main/timeout, ревизия exit-хвоста — только после стабильности на кремнии).

## 6. Анти-скоуп

Порт branchless RX/TX v2; HW-USB блок; дробная PLL; 50 МГц/33 такта; симулятор BM-310;
RAM-first; кварцы <10 МГц (PLL-лимит; бескварцевость — трек CLK-B, не через низкий
кварц); правки C-слоя сверх четырёх швов Р3 (дескрипторы в RAM — линкерное размещение;
REBOOT_TO_BOOTLOADER — объявленный шов); USB_TERMINAL на WG015.

## 8. Definition of done

demo_hidapi и бутлоадер стабильно работают на К1921ВГ015 @48 МГц с кодом во флеше (или
