# План порта rv003usb (битбанг LS USB) + бутлоадера на К1921ВГ015

Статус: **v2**, 2026-07-31. v1 → v2: интегрированы находки адверсариальной панели
(redteam_findings.md, линзы timing+flash; линзы boot/arch/complete — ожидают перезапуска,
см. STATE.md). База фактов: `chip_info.md` (+CORRECTIONS), `research/*.md`,
`stack_portability.md`, `branch_notes.md`, `shared_chat_notes.md`.

## 0. Цель и рамки

Рабочий битбанг LS USB (1.5 Мбит/с) стек + USB HID бутлоадер на К1921ВГ015 @ 48 МГц,
32 такта/бит. Код — во флеше (flash-first); TCM — только как измеримо обоснованный отход.
База — master (branchless-ветка = cycle-exact артефакт CH32V003, branch_notes.md).
Не переделывать архитектуру при появлении третьего таргета.

**Честная формулировка flash-first** (итог red-team): документированный префетчер
(2×128 бит) покрывает только straight-line код; реальный RX-движок ветвится по данным
между путями, разнесёнными на ~300 Б (S:298-424), т.е. на уровне документированного
железа промахивается почти на каждом бите. Флеш-исполнение жизнеспособно, если
**кэш команд 2 КБ** (РП-интро; «Cache-I 2 кБайт» в даташите) делает многопутевую петлю
повторяемо-детерминированной. **Вердикт research_bm310.md: кэш — опция ядра BM-310S6**
(CloudBEAR: «Опциональный кэш инструкций», конфигурируемый; у sibling-Миландра BM-310S
кэша нет — per-licensee опция), кэш-CSR нет, только fence.i → **неотключаем**; CEN,
вероятно, гейтит НИИЭТ-овский префетч 2×128 бит (остаточная неопределённость — бенч P1.4в).
Следствия: G1-бенч с вытеснителем — единственный честный тест флеша; fence.i — легальный
инструмент принудительного «холодного» старта в бенчах. Разбор -mfix-cloudbear-0001
(эррата №5): NOP нужен перед fdiv/fsqrt И div/divu/rem/remu, когда операнд загружен из
флеша — загрузки данных из флеша имеют переменную латентность (поздний форвардинг) —
микроархитектурное доказательство правила Р3 (данные тактованного пути — только
TCM/регистры; div в битовом пути и так нет). TCM подтверждён: два независимых порта
128К/32-бит, 0-wait, конфликт только I+D на одном порту → банк-сплит Р6 обоснован.

## 2. Архитектурные решения

**Р1. База — master** (75d926a). Branchless-идеи — только после P6, по измерениям
(tier-b ACK-first — первый кандидат, R9).

**Р2. Один исходник `rv003usb.S`, зонная параметризация.** Обоснование и отход
(форк-копия при >~30% строк под #if, решение в конце P3) — как в v1. Зоны:
- z1: константы GPIO (база, смещения), маски пинов;
- z2: RX-сэмплы: `c.lw INDR(+8)` → `c.lw DATA(+0)`;
- z3: TX-стора — **по-сайтовый мэппинг** (6 BSHR-сайтов V003 ≠ один приём;
  red-team T1-blocker):

  | Сайт V003 | Семантика | WG015 |
  |---|---|---|
  | S:767-768 preset K до захвата | абсолют | DATAOUTSET=DP + DATAOUTCLR=DM (2 store) до OUTENSET; вариант — 1 запись MASKLB (маска D±) |
  | S:837 преамбула/токен | toggle | DATAOUTTGL, безусловный store |
  | S:948 send_zero_bit | toggle | DATAOUTTGL=D±mask |
  | S:914-927 one-bit путь | **нет store** | без store (паритет тактов балансирует z7) |
  | S:1024 insert_stuffed_bit | toggle | DATAOUTTGL=D±mask |
  | S:992-993 SE0/EOP | абсолют (обе вниз) | DATAOUTCLR=D±mask (1 store) |
  | S:997-998 J-park | абсолют | DATAOUTSET=DM (+DP уже 0 после SE0) |

  Инвариант: DATAOUT-биты D± валидны перед каждым захватом линий (J-park поддерживается
  между пакетами). z7 перебалансирует изменившиеся последовательности инструкций в
  тактованных слотах (не только адрес store).
- z4: turnaround: preset (см. z3 первую строку; **никогда не полный DATAOUT** — на
  порту сидит DPU=C2, ред-тим T3) → `OUTENSET=D±mask` (захват) … `OUTENCLR=D±mask`
  (отпуск). Итого ~3 store — всё ещё короче V003.
  **Внимание**: V003 здесь намеренно ставил режим «2 МГц» (слю-лимит, S:759-764);
  на ВГ015 slew-контроля нет (F4) → TX-фронты обязательны к замеру в P4 (риск R12).
- z5: вход/выход ISR: mtvec(direct) → хендлер; ack: GPIO INTSTATUS(W1C) → PLIC
  claim/complete в хвосте, INTSTATUS строго раньше complete; mret. Хук чужих IRQ:
  слабый символ, диспетчеризация по значению claim из MICC.
- z6: keepalive: SysTick CNT → rdcycle (вне битового пути). Серво-механизм (замер
  SE0→SE0 кадра и подстройка клока) НЕ удаляется, а расслаивается: измерение кадра —
  общий код, актуатор трима — per-target плагин (V003: RCC.HSITRIM; WG015: пусто на
  кварцевых сборках, резерв под трек CLK-B);
- z7: паддинг-макросы по числам P1 (механика VOOXDELAY); леджер включает маркер-стора
  Р10 (DBG0 в сэмпл-точках, DBG1 в событиях) и TUNE-вариант паддинга;
- **z8 (новая, ред-тим FL6): far-branch трамплины** asm↔C для TCM-варианта
  (`lui/addi+c.jr` — готовый прецедент V00x, S:465-470/497-515): зона готовится в P2,
  чтобы отход R1 был действительно link-time. Формулировка v1 «цена нулевая, код не
  меняется» — неверна и снята: флеш и TCM разнесены на 1 ГБ, `c.beqz`→C-хендлер не
  дотягивается; цена отхода = включение z8 + перевывод тактов диспатча.
Гарантия: **бит-идентичность V003-сборки** до/после (check-цель Makefile).

**Р3. C-слой единый.** Три шва + `usb_port_wg015.h`. Дополнение (ред-тим FL5):
**данные, читаемые в битовом пути, обязаны жить в RAM** — включая дескрипторы
(TX-петля читает их побайтно изнутри тактованного слота, S:887-890, а D-code имеет
приоритет над I-code → стойло инструкций середине слота). Реализация без правки C:
линкером — `.rodata` конфигового TU (дескрипторы) кладётся в data-секцию (копируется
стартапом в RAM). Это уточнение H3, а не изменение протокольного слоя.

**Р4. Тактирование.** Как v1: HSE→integer PLL→48.000; конфиги для 10-25 МГц готовы
(research_clocks.md §2); дефолт 16 МГц; дробный режим запрещён; REFSEL — эксперимент P0.
LAT=1 — **рабочая гипотеза с гейтом целостности** (R11): вендор+сообщество ездят на
LAT=3@50, эррата №5 доказывает реальность флеш-hazard'ов, РП-таблицы ошибаются
(прецедент ADCSD) → P1 включает integrity-стресс при LAT=1, эскалация LAT=2 =
полный перезапуск P1 (все числа LAT-специфичны).

**Трек CLK-B (параллельный уровень): работа без кварца — целевая.** Кварц — стартовая
ступень, не конечное состояние. Документированного пути нет: PLL требует fREF 10–30 МГц
и fVCO 200–1600 МГц при FBDIV≤160, HSI фиксирован ~1 МГц (1×160=160 МГц — вдвое ниже
VCO-минимума; research_clocks.md §1). Исследовательские ходы (по мере доступа к железу,
не блокируют основной трек): (а) out-of-spec запуск PLL от HSI через REFSEL=0 — мультиплексор
физически существует (рис. 4.1), эксперимент на час: лочится ли и на чём; (б) поведение
VCO ниже документированного минимума; (в) недокументированные ручки HSI (PMURTC.HSI_TRIM —
шаг груб, ~8%/LSB по habr, но нижний слой для серво); (г) вопрос в NIIET/CloudBEAR-доки.
Архитектурная страховка уже в z6: серво-хук сохранён, актуатор — плагин. Если путь
найдётся — бескварцевый уровень включается конфигом, без перестройки стека.

**Р5. Пины.** D+=C0, D−=C1, DPU=C2; резерв B2/B3/B4. Внешний 1.5К DPU→D−.
QUAL off, SYNC base (2 такта — константа фазы, вычитается из бюджета, не джиттер).
LOCKSET на D±-конфиг. С P0 на плате предусмотреть посадочные места последовательных
R на D± (лечат и RX-дребезг R5, и TX-фронты R12).

**Р6. Размещение кода: placement-agnostic.** Критические секции маркируются; линкер
решает FLASH (default) | TCM-A (+данные/стек в TCM-B). Отход в TCM = смена размещения
секции **плюс z8-трамплины** (готовятся заранее, см. Р2). Гипотезы:
- H1: горячее множество (**asm-ISR + C-хендлеры turnaround-пути** — они исполняются
  внутри того же прерывания, c:162-238) детерминированно сидит в кэше команд 2К —
  проверяется P1 с **противником-вытеснителем**, не тихой петлёй;
- H2 (v1) **опровергнута** на уровне документированного префетчера (см. §0) — снята;
- H3 → правило Р3 (данные битового пути в RAM, включая дескрипторы).

**Р7. Прерывание.** mtvec(direct) → хендлер; сэмпл D− пятой инструкцией; 8-слотовый
edge-catcher. Приоритеты (исправлено, ред-тим T6): наш источник — prio 7 (max);
прочие нужные — ниже нашего, но **выше threshold** (иначе они мертвы навсегда);
невытеснение USB-ISR обеспечивает mstatus.MIE=0 на всё время трапа (MIE внутри не
включать); gateway страхует только от повторного входа своего же источника.
Контракт остальных хендлеров ≤~40 тактов (README:94) сохраняется.
Абсолютная граница входа (ред-тим T5): keepalive-SE0 длится 2 бита = 64 такта, и
классификация делается ПЕРВЫМ сэмплом → медиана(фронт→1-я инструкция) + 4 инстр +
lw GPIO + 2 такта синхронизатора **≤ ~55 тактов** — жёсткий гейт P1.3; провал =
головной стаб в TCM-A обязателен (и тогда TCM→flash переход тела меряется отдельно).

**Р8. Бутлоадер.** Как v1 (лейаут 4К @0x8000_0000, app @+0x1000; вход: RTC_REG[0] +
RSTSYS + таймаут/кнопка; блобы в RAM c глобальным IRQ-off на время BUSY; пересчёт
TACCR..TPGSR на 48 МГц; хост-CLI из busbflash; OpenOCD DCVostok / SERVEN; свой
tiny-boot; SECRET-механика с новыми адресами). Детали ревизует линза boot (в очереди).

**Р9. Сборка.** Как v1: Makefile.wg015; GCC 13.2 riscv-none-elf; `-march=rv32imc_zicsr`
(без F — эррата №5 обходится стороной); вендорим только K1921VG015.h; старт/ld свои.

**Р10. Наблюдаемость: маркеры нулевой интрузивности + hw-in-loop тюнинг.**
Прецедент — апстримовский RV003USB_DEBUG_TIMING (store всегда исполняется, меняется
только адрес: TIM1 или пустышка, S:30-38). На ВГ015 чище:
- **Маркер** = всегда присутствующий `sw dbg_mask, DATAOUTTGL(port)`; TGL с нулём —
  архитектурный no-op. Off: dbg_mask=0, on: dbg_mask=бит пина. Поток инструкций и такты
  идентичны в обоих режимах — отличие только в данных; маски грузятся из TCM-переменных
  при входе в ISR (управление в рантайме, без перепрошивки). Store — полноправный член
  32-тактного леджера (цена из бенча P1.1, учитывается z7).
- **Каналы**: **DBG0 = сам DPU (C2)** — пин внешней подтяжки обязателен в любом случае,
  а внутри пакетных окон он электрически замаскирован (при RX линии держит хост, при TX —
  мы; драйвер ≪ 1.5К: инъекция ~2.2 мА через 1.5К сдвигает уровень на десятки мВ).
  Правила: тоглить только в окнах, где шина активно ведётся; перед любым отпусканием
  шины/уходом в idle — принудительный re-park `DATAOUTSET=DPU` в некритичном хвосте
  (чётность тоглов не отслеживаем — паркуем безусловно). LA цепляется на сторону пина MCU.
  Роль: «сетка» (тогл у каждого RX-сэмпла; границы TX-ячеек) → положение точки выборки
  в глазе, джиттер, периоды TX-ячеек. **DBG1 = C3 (опционально)** — «события»
  (1-я инструкция ISR, done_preamble, SE0/keepalive, старт/конец TX); не распаян —
  маска 0, ничего не меняется. Отдельный пин под сетку не нужен вовсе.
- **Тюнинг-паддинг**: в TUNE-сборке паддинг-макрос = `jr` в nop-след со смещением из
  TCM-переменной (гранулярность 1 такт, крутится в рантайме под LA); финальные
  константы запекаются в продакшн-нопы, маркеры DBG0 верифицируют результат.
- Бонус RV32I: верхние 16 регистров (x16+) свободны от E-чистого asm — внутри ISR
  используются под маски/базы без давления на слоты (постоянная резервация запрещена —
  C-ABI).
- P1-бенчи используют те же маркер-макросы с первого дня (бенч — первый потребитель).

## 3. Тайминг-модель

32 такта/бит. **Окно −4..+6 (S:186-188) — стартовый фазовый допуск V003-сборки, не
переносимая константа** (ред-тим FL4): на ВГ015 перевыводится заново свипом
искусственного сдвига сэмпла (перенесён из P6 в P3). Бюджет дрейфа: пакет до
**~102 слотов** (88 бит + worst-case стаффинг, T9). Ошибки слотов интегрируются в фазу
(ин-пакетного ресинка в master нет) → критерий G1 — по кумулятивной экскурсии, не по
гистограмме периодов (FL3). Статический паддинг лечит только детерминированные
константы путей; истинная непересчитываемая случайность = провал флеша.
Измеряемые величины: F12-список + стоимость lw/sw MICC и INTSTATUS + хвост ISR
(выход+перевход: хост-ACK приходит через ~2 бита + SYNC ≈ 300 тактов после нашего EOP —
бюджет tail+entry < ~200 тактов, T7).

## 4. Фазы

**P0. Стенд.** Тулчейн 13.2 + OpenOCD DCVostok + плата; blink; UART-консоль; PLL 48 МГц
(REFSEL-эксперимент; CKO на C7 под контроль частоты); rdcycle работает.
Выход-чеклист: **маркировка чипа записана** (G1 валиден только для измеренной ревизии,
FL8); **LA ≥100 МС/с подтверждён** (иначе P1.5 не измерить; замена — input-capture
таймером, хуже); посадочные места R на D± (Р5).

**P1. Калибровка** (`wg015_bench/`, результаты → `calibration.md`; все числа помечаются
LAT-значением). Правила измерений: rdcycle — только агрегатно (CSR осушает конвейер,
внутрислотовый rdcycle искажает картину, FL9); пер-слотовые времена — только LA.
1. lw/sw GPIO из TCM (rdcycle-пары, агрегатно по N);
2. taken/untaken branch; выровненный/невыровненный таргет;
3. вход в IRQ: фронт→тогл первой инструкцией; **медиана И разброс**; хендлер в TCM и
   во флеше; **гейт: медиана-путь ≤ ~55 тактов** (Р7); + TCM-стаб→flash-тело переход;
4. флеш-профиль: straight-line;бранч-мисс за 32 Б; CEN=0/1 семантика (что реально
   меняется — заодно ответ «кэш = CEN?»); из TCM — референс; **integrity-стресс LAT=1**
   (чек-суммы большого региона, длительно) — прекондиция G1 (R11);
5. **слот-эмуляция, изоморфная реальному коду** (FL2-blocker): ≥3 тела слота на
   расстояниях 100-300 Б, выбор пути по PRBS-данным, обратный бранч каждый слот
   (или ранний порт RX-скелета z1/z2 как генератор нагрузки); из флеша и из TCM;
   **противник-вытеснитель** (между «пакетами» исполнять >2-4К постороннего флеш-кода;
   один под-путь стартует холодным серединой пакета — FL1-blocker); лог кумулятивных
   сумм по ≥10^4 пакетов, cold vs warm;
6. lw/sw MICC(0x0C200004) и INTSTATUS; back-to-back IRQ: полный хвост + перевход,
   зазор по LA (T7).
**Гейт G1** (переписан, FL3/FL4): флеш проходит, если при LAT, прошедшем integrity,
и при активном вытеснителе: (а) каждый путь повторяемо-детерминирован
(нулевая дисперсия повторов) — тогда пути триммируются паддингом z7 в ровно 32; либо
(б) остаточная worst-case кумулятивная экскурсия по скользящим окнам ≤102 слотов на
≥10^4 PRBS-пакетов укладывается в перевыведенный стартовый допуск (P3-свип) минус
2-тактовый запас минус константа синхронизатора. Иначе — TCM-A (+z8-трамплины).
Головной стаб — по гейту бенча 3.

**P2. Скелет таргета.** Как v1 + подготовка z8-зоны; дескрипторы конфигового TU —
в RAM через ld (Р3). Выход: скелет зелёный, бит-идентичность V003.

**P3. RX.** Зоны z1/z2/z5/z6/z7 (+маркеры Р10 сразу); **свип сдвига сэмпла — теперь
это TUNE-паддинг Р10 под LA** (карта допуска на цели, кормит G1-критерий (б));
положение сэмпла в глазе документируется по DBG0; приём реального трафика: SETUP
ловится, CRC сходится, ≥10 мин без потерь. Фиксация решения Р2-отхода.

**P4. TX + энумерация.** Зоны z3/z4 (по-сайтовой таблице); ACK; турнэраунд ≤7.5 бт по
LA; **TX-фронты D± на разъёме против конверта 75-300 нс** (T4/R12), при выходе — подбор
последовательных R; энумерация, demo_hidapi; ≥100 переподключений, soak ≥1 ч.

**P5. Бутлоадер.** Как v1 (+ ревизия после boot-линзы). Первый блоб — тест юнита
записи 16/64 Б. Критерий: 100 циклов reflash без JTAG.

**P6. Стабилизация.** Маргин-карта (свип уже в P3 — здесь регресс на финальном коде);
README; ревизия анти-скоупа (tier-b по измеренному турнэраунду); чистка diff.

## 5. Риски

| R | Риск | Триггер | Отход |
|---|------|---------|-------|
| R1 | Флеш недетерминирован | G1 (бенч 5 с вытеснителем) | секция→TCM-A + z8-трамплины (подготовлены в P2) + перевывод тактов диспатча |
| R2 | Вход в IRQ: медиана >55 или разброс > catcher | бенч P1.3 | головной стаб в TCM-A; QUAL off default |
| R3 | lw GPIO > 8 тактов | бенч P1.1 | перестройка фазы сэмпла в слоте |
| R4 | REFSEL/PLL | P0 | SDK-последовательность |
| R5 | RX-дребезг (нет Шмитта) | soak P4 | последовательный R (место с P0); QUAL 3-sample — крайний резерв |
| R6 | Юнит записи 16 vs 64 Б | первый блоб P5 | блоб параметризован |
| R7 | ISR при флеш-BUSY | design-time | глобальный IRQ-off в блобе (Р8) |
| R8 | 4К лодеру мало | линковка P5 | 8К, app @+0x2000 |
| R9 | Турнэраунд >7.5 бт | LA P4 | tier-b ACK-first (3735518) |
| R10 | Лимиты/обрывы | постоянно | всё в файлах, коммит на шаг, STATE.md |
| R11 | LAT=1 маргинален | integrity-стресс P1.4 | LAT=2 + **полный перезапуск P1** |
| R12 | TX-фронты вне 75-300 нс (slew-контроля нет) | LA/скоп P4 | последовательные R/RC на D± |
| R13 | G1-вердикт не переносится на другую ревизию кремния | смена маркировки | перезапуск бенчей P1 на новом экземпляре |

## 6. Анти-скоуп

Как v1: branchless-порт; HW-USB; дробная PLL; 50 МГц/33 такта; симулятор BM-310;
RAM-first; кварцы <10 МГц; правки C-слоя сверх швов Р3 (уточнение: перенос дескрипторов
в RAM — линкерное размещение, не правка кода).

## 8. Definition of done

Как v1 + G1-вердикт задокументирован числами в calibration.md с привязкой к маркировке
чипа и LAT; TX-фронты измерены; V003-сборка бит-идентична.
